## 背景

`2026-07-14-momentum-strategy-page-design.md` 定義的 B1~B5 資料層（`scan_momentum_health()`、
`scan_bullish_alignment_new_high()`、`scan_consecutive_limit_up()`）已經全部實作完成（commit
`faa54b8`），但該文件的狀態表沒有回頭更新，且明講「不含實際視覺呈現」。本文是那個下一階段。

**Brainstorming 過程中兩次推翻早期方案，記錄决策脈絡**：

1. **原始方案（5 個各自獨立區塊）被推翻**：最早提案照「動能派 5 個問題」切成 5 個獨立排行榜
   （①主流族群 ②族群內最強 ③能不能進 ④該不該出 ⑤最強型態），使用者要自己在腦內把 5 張表拼起來
   才能得出結論。Cody 指出這不是「一體成形」——筆記第三十條的**五級強弱分類本身就是操作決策樹**
   （超強=隨時加碼、強=續抱、整理=反彈可出、弱=直接出清、超弱=反手放空），每一級直接對應一個動作，
   不是貼在股票旁邊的裝飾性 badge。**收斂決定：頁面核心改成單一「族群→個股→動作」清單**，①主流
   族群降級為篩選範圍（不是結論），②③④收斂成同一張表裡每檔股票的欄位，⑤獨立維持（全市場掃描，
   不受族群篩選限制）。
2. **「照抄回測 backtest.py 就能驗證這些訊號」被推翻**：Cody 指出 B2（出場三原則）用現有
   `run_backtest()`（固定 D+1 進場、固定 D+1+H 出場）**框架性地測不了**——`run_backtest()` 本身
   的 plan 早就把「規則出場」列為 Out of scope。B1/B3/B4/B5 理論上可套但也有真實偏誤（還原股價
   缺口、universe 非 point-in-time、regime 相依）。**本次不處理回測驗證**，那是另一個獨立任務，
   不在本文範圍。
3. **筆記覆核發現的兩個結構性缺口，補回設計**：Cody 追問「大盤好/大盤不好怎麼辦、停利停損呢」，
   逐條覆核筆記後發現原設計完全沒處理「大盤 regime 如何改變整頁姿態」與「停利停損的哲學是什麼」，
   詳見 §3、§4。

## 視覺風格（沿用既有系統，不自創）

延續本專案 2026-07-15 最新一版族群總覽頁 mockup
（`docs/superpowers/mockups/2026-07-15-index-v18-inline-expand.html`）已確立的設計 token，不重新
發明一套色系/字體：

```css
--bg:#080B12; --panel:#0F1420; --panel-2:#161D2C; --panel-3:#1E2738;
--border:#293346; --border-2:#37435C;
--ink:#DADFE8; --ink-2:#98A0B4; --ink-3:#636B80;
--up:#E6432F; --down:#37B25C;                    /* 紅漲綠跌，Cody 2026-07-14 已定案的方案 */
--accent:#F0BB55; --accent-dim:#B98A3A;
--tier-super:#F0BB55; --tier-strong:#4FC46A; --tier-mid:#8B94AC;
--tier-weak:#E08A3E; --tier-superweak:#E6432F;
--serif: Georgia,"Iowan Old Style","Source Serif 4","Noto Serif TC",serif;   /* 標題 */
--sans: "Public Sans",-apple-system,"PingFang TC","Microsoft JhengHei","Segoe UI",sans-serif; /* 內文 */
--mono: ui-monospace,"IBM Plex Mono","Cascadia Code","Roboto Mono",monospace; /* 數字/代號 */
```

- 深色為主，`:root[data-theme="light"]` 提供對應淺色 token（跟現有頁面一致的明暗切換模式）。
- 五級 tier 顏色（`--tier-*`）跟族群總覽頁的族群熱度分級**共用同一組色票**，全站「超強/強/整理/弱/
  超弱」用色一致，不會因為換頁面而讓使用者重新學習一套新的顏色語意。
- 數字一律 `tabular-nums`（`.tabular` class），確保欄位對齊。

**架構決定**：本頁新開一個獨立 generator（暫定 `export/momentum_generator.py`），不強行共用
`chips_generator.py`/`html_generator.py` 的既有元件——資料形狀（`rs_rank_pct`、
`exit_3_rule_triggered`、`limit_up_streak` 等）跟既有頁面完全不同，硬套會增加既有 generator 的
複雜度。CSS 設計 token（顏色/字體變數）可以複製共用，但 HTML 結構與 JS 邏輯獨立成檔，比照
`chips_generator.py` 自成一檔的既有慣例。

### 3.1 為什麼不是舊 spec 的「5 個並列區塊」

同族群裡「誰最強」「能不能進」「該不該出」三個問題，答案必須**同時**作用在同一檔股票身上才有意義
（筆記十二：「不需要分散產業，買最強的那一籃」；筆記三十：「同族群中選最強那一檔」）——拆成三張表
會強迫使用者自己拿著三份清單交叉比對。收斂成一張表後，②族群內排名、③進場確認、④出場警示三者
共同收斂成 tier 欄位的**單一動作結論**，細節（命中哪幾條）留給展開列顯示，而不是預設就攤在主表上
造成資訊過載。

## 4. 大盤狀態橫幅（新增，回應筆記「大盤好/大盤不好」的應對邏輯）

### 資料來源

`processors/performance.py::classify_market_regime(taiex_change_pct, breadth_ratio, divergence)`
（既有、已實作、2026-07-09 完成），回傳 `{tier, is_concentrated, concentration_direction}`，
`tier ∈ {大漲, 小漲, 持平, 小跌, 大跌}`。

### 視覺與文案分兩種模式

| 模式 | 觸發條件 | 橫幅左邊框色 | 文案基調 |
|---|---|---|---|
| **平穩模式**（calm） | `tier ∈ {大漲, 小漲, 持平}` | `var(--tier-strong)`（綠） | 照正常①-⑤流程操作，不需啟動換股警戒 |
| **急殺模式**（selloff） | `tier ∈ {小跌, 大跌}` | `var(--tier-superweak)`（紅） | 「不是清倉不動的時候」——找還在紅盤/跌得比大盤少的個股換股集中，附帶下方 [換股警戒區塊] |

### 文案依據（明列筆記出處，供 Cody/未來維護者對照原文）

- 平穩模式：無特殊文案，僅顯示大盤數字。
- 急殺模式：「大盤急殺，不是清倉不動的時候——先看還在紅盤、跌得比大盤少的個股，把弱勢股（尤其
  跌停鎖死）換到最強的1～2檔，資金集中不分散。急殺撬開最後那幾檔鎖漲停時是換股的黃金時間，不是
  逃跑時機。」
  依據：筆記一（買紅不買綠：大盤大跌時的正確動作）、筆記二十三（換股操作實戰）、筆記十四（大殺盤
  情緒點抓法——僅取用其「找最後撐住的強股」核心邏輯，**不含**盤中掛定價單等執行細節，那屬於
  `2026-07-09-momentum-notes-scan-mapping.md` 已排除的「盤中戰術」範圍）。

### 橫幅顯示內容

```
[tier 文字，紅/綠/灰]  [加權指數漲跌% · 上漲家數比 breadth_ratio]   [資金集中度診斷 badge]
[展開的說明文字段落，依模式顯示對應文案 + 出處來源]
```

`concentration_direction`（`None`/`權值股撐盤`/`中小型輪動`）直接顯示成右側 badge，供使用者判斷
這波是真的普漲還是少數權值股撐盤（呼應大盤分級儀表板 spec 原文的用途）。

## 5. 停利/停損哲學提示（新增，回應筆記對固定 % 停利停損的立場）

### 為什麼需要這個區塊

覆核筆記後確認：**動能派沒有「停損 X%」「停利 Y%」這種固定百分比機制**。停損就是出場三原則本身
（筆記三：「三個條件同時滿足才出場」，跟價格跌幅百分比無關）；停利也不存在固定目標價——賺的部位
「漲時加碼，跌時全出」（筆記七、八），靠倉位紀律而非價格目標控制風險。唯一例外是筆記三十二（週K/
月K 格局判斷）的「買進當天低點」防守價，但那是**另一套用於長線格局判斷的機制**，跟本頁日線動能
掃描的主邏輯不同層級，本次不做成頁面欄位，避免跟主流程混淆。

若頁面完全不提這件事，使用者會自然預期看到「停損-8%／停利+20%」這類欄位，找不到會誤以為是遺漏。
**這個提示區塊的作用是把「沒有」講清楚，變成刻意的設計决定，不是疏漏。**

### 顯示文案

> 本頁沒有停利/停損百分比欄位——動能派不用固定%，出場三原則本身就是停損機制（跌破五日線+五日線
> 下彎+重挫長黑，三者同時成立才出，不是價格跌到某%才砍）。倉位紀律取代停利：分批進場、往上加碼、
> 絕不往下攤平，賺的時候讓它繼續跑，直到出場三原則觸發為止。

固定顯示在大盤狀態橫幅之下、五級 legend 之上，不可收合（首次上線先常駐顯示；若之後使用者反應
太佔版面，可以改成一次性 tooltip 或 FAQ 連結，但**不在本次範圍內預先設計收合邏輯**，YAGNI）。

## 6. 換股警戒區塊（新增，僅急殺模式顯示）

### 觸發條件

大盤狀態橫幅判定為 `急殺模式`（`classify_market_regime().tier ∈ {小跌, 大跌}`）時才渲染這個區塊；
平穩模式完全不顯示（不是顯示空清單，是整個區塊不存在，避免平時版面雜訊）。

### 資料邏輯：弱中透強候選 vs 跌停立刻砍

- **弱中透強候選**：個股今日跌幅 明顯小於 大盤同期跌幅（呼應筆記三十三「弱中透強接刀法」核心
  邏輯：「大盤兩次下殺，某檔沒有創新低＝弱中透強」；本頁簡化為單日相對表現，不做筆記原文的兩次
  下殺比對——那需要盤中逐筆資料，超出本頁日線掃描範圍）。判斷欄位沿用 B4 `rs_market_score`
  （個股近5日報酬 − universe 等權平均近5日報酬，`2026-07-14` spec §3.4 已定義，這裡取其邏輯而非
  重新定義新欄位——`rs_market_score` 本來就是「跟大盤比」的相對強弱，急殺當天的個股表現只是它的
  一個特例輸入）。
- **跌停鎖死·立刻砍**：`change_pct` 觸及跌停（沿用 `screener/signals.py::_LIMIT_UP_PCT` 對應的
  跌停版本門檻，若專案目前只有漲停常數沒有跌停常數，需在實作 plan 階段新增對稱的
  `_LIMIT_DOWN_PCT`）。

### 顯示形式

一張精簡對照表（股票/今日漲跌/vs大盤 pp 差距/判斷結論二選一：`弱中透強·可換入` 或
`跌停鎖死·立刻砍`），表格下方一行動作提示：「賣出『跌停鎖死·立刻砍』的持股，資金集中換進『弱中
透強·可換入』——同天執行，不分批猶豫」（依據筆記二十三换股實戰的操作節奏，換股是同天內完成，
不是分批試探）。

## 7. ②③④ 主表：族群→個股→動作合一清單

### 7.1 族群篩選 pill（區塊①）

橫向捲動的 pill 列表，每個 pill 顯示：族群名稱、族群排名（`#1`/`#2`...）、族群當日漲跌%、
輔助說明（例如「連3日主流」——沿用既有族群連續在強勢榜的天數概念，若現有函式沒有這個欄位，
實作 plan 階段需要新增或確認資料來源，本文不預先假設一定有現成欄位）。點選 pill 切換下方主表
篩選範圍，預設選中族群強度排名第一名。

### 7.2 主表欄位

| 欄位 | 資料來源 | 顯示形式 |
|---|---|---|
| 股票（代號+名稱） | `scan_momentum_health()` 輸出 `stock_id`/`stock_name` | 代號用 mono 小字、名稱用 serif |
| 現價 | `close` | tabular mono |
| 漲跌% | `change_pct` | tabular mono，紅漲綠跌 |
| 族群內排名 | 需在 `scan_momentum_health()` 或消費端新增「族群內依 `rs_score` 排名」邏輯（目前該函式回傳 `rs_rank_pct` 是百分位小數，不是名次，實作 plan 階段需決定是否額外算出 `#N/total` 形式，或直接沿用百分位改用進度條呈現，不強求名次數字） | `#N/total` + 進度條，或改用 `rs_rank_pct` 直接驅動進度條寬度 |
| 五級判斷＋動作 | `strength_tier`（`scan_momentum_health()` 既有欄位）映射到動作文字（見 §7.3） | tier chip，色點+文字 |
| 展開箭頭 | 純前端狀態 | 點列展開/收合 |

### 7.3 五級 → 動作文字映射（明列，避免實作時各自詮釋）

| `strength_tier` | 動作文字 | 額外條件 |
|---|---|---|
| 超強 | 超強·隨時加碼 | 無 |
| 強 | 強·續抱 | 無 |
| 整理 | 整理·反彈可出 | 無 |
| 弱 | 弱·直接出清 | 無 |
| 超弱 | **預設**：超弱·直接出清觀望；**若當日 `change_pct` 觸及跌停**：超弱·跌停可反手放空 | 放空文案需額外查當日是否跌停（見 §7.4） |

### 7.4 放空條件收斂（筆記三十四的限定）

筆記原文：「逆轟不空漲停的股票，只空跌停的股票」——不是任何「超弱」都建議放空。`strength_tier`
判斷本身只吃均線排列/相對強弱，不包含「今天是否跌停」這個資訊，因此**動作文字判斷需要額外讀
`change_pct` 是否觸及跌停常數**，兩個條件（`strength_tier == '超弱'` 且 `change_pct <= 跌停門檻`）
同時成立才顯示「反手放空」字樣，否則超弱只顯示「直接出清觀望」，不主動建議放空方向。

### 7.5 個股展開面板（點列觸發）

三欄並排（窄螢幕 <900px 時改直向堆疊）：

**欄1：進場/出場三原則勾選清單**
- 進場三原則：帶量長紅突破前高 / 創波段新高 / 短中長期多頭排列，逐條勾選（✓/—）。
- 出場三原則：跌破五日線 / 五日線下彎 / 重挫長黑，逐條勾選。
- 資料來源：`entry_confirmed`（B2，需拆解成三個子條件個別回傳，目前 `scan_momentum_health()`
  只回傳合併後的 bool，**實作 plan 階段需要決定是否要讓函式額外回傳三個子條件的個別真偽值**，
  或消費端自行從 `ma_alignment`/`ma5_slope_down`/現有欄位反推——這是本文發現的一個介面缺口，
  留給下一階段 plan 處理，不在本文擅自假設）。

**欄2：均線數值（今日）**
- 收盤價 + MA5/MA10/MA20/MA60 實際數字，價格高於/低於該均線用紅/綠上色（沿用漲跌色語意，
  「站上均線」視覺上等同「相對均線是漲的」）。
- 說明文字：「MA20 純參考，不參與多頭/空頭排列判斷」（呼應 spec §1.1 的收斂決定，避免使用者
  誤以為 MA20 也是判斷依據之一）。
- 資料來源：`scan_momentum_health()` 既有回傳的 `ma5`/`ma10`/`ma20`/`ma60`。

**欄3：相對強弱（近5日）**
