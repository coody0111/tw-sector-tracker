# 族群排名歷史即時從 daily_prices 重算，不存週快照表

**背景**：「排名進出榜」跟「歷史出現紀錄」都需要「這個族群上週/近5週排第幾名」的歷史排名資料。
有兩種做法：①每週固定時間點把當時的排名寫進一張快照表存起來 ②即時從 `daily_prices` 全歷史
用「今天的族群分類」回頭算出過去每一週的排名。

**決定**：採用②，即時重算，不建快照表。

**why**：這個網站是靜態產生器（`main.py` 每天跑一次產生 HTML），不是即時查詢的 web app，
即時重算不會有效能壓力。更重要的是族群分類本身會變動——這次會話才把「工業電腦」從
「電腦周邊」拆出來，筆電那邊也還有一個「族群分類校正層」的設計在討論中。如果存快照表，
分類修正後舊快照不會跟著更新，會出現「工業電腦沒有歷史排名」這種不一致（因為快照當時
它還叫電腦周邊）。即時重算則會自動用當下最新的分類回推歷史排名，不會有這個問題。

**代價**：如果之後真的需要「那一週當時系統認為的排名」這種嚴格時間點快照（例如要驗證
「這個功能上線第一週實際顯示過什麼」），這個做法拿不到，因為排名會隨著分類修正而改變。
