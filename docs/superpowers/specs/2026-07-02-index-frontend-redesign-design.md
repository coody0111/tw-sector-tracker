# 族群總覽頁（index.html）前端重新設計

**日期**：2026-07-02
**範圍**：`docs/index.html` 一頁，不含 `chips.html`／`patterns.html`（資料補齊後再做）

## 背景與目標

目前 `docs/index.html` 是 Python（`export/html_generator.py`）直接產生的純靜態 HTML，內嵌所有 CSS/JS。版面採卡片式（`mc-grid` 主族群卡片 → 展開子族群 mini-card grid → 再展開個股表格），三層點擊才看得到個股資料，且排行榜（Top10）跟主列表資訊重複。

這次重做目標：
1. 技術路線改成 React + Vite，元件化、方便日後維護擴充
2. 排版邏輯改成「編輯風格清單」（財經媒體式排行榜），拿掉卡片感、拿掉重複的 Top10
3. 排名/訊號類資訊（累積排名、排名升降、連漲連跌、量能異常）視覺上更醒目

視覺風格（配色、字體、圓角、hover 效果等，見 `DESIGN.md`）**不是這次重點**，維持現有深色主題不變。

## 技術路線

- **框架**：React + Vite
- **部署**：不用 GitHub Actions。流程改成：
  1. `main.py` 產生 `docs/data.json`（取代直接產生完整 HTML）
  2. 本機執行 `npm run build`，Vite 產生靜態檔案到 `docs/`
  3. `data.json` + build 產物一起 `git commit` + `git push`，跟現有 GitHub Pages 部署方式相容，不需要新增 CI/CD
- **資料流**：`data.json` 在 build 時由前端讀取（fetch 或靜態 import 皆可，實作階段再定），不走任何後端 API——整個系統維持「純靜態站」的性質不變

## 排版結構

### 響應式雙模式

- **桌機（寬螢幕）**：A+B 混合——左側固定寬度排行榜清單（大名次數字＋族群名＋漲跌%），右側固定明細區。點左邊某族群，右邊內容更新，整體頁面高度不隨點擊變化。
- **手機（窄螢幕）**：A+C 混合——單欄由上到下的排行榜清單，點擊某族群直接在該列下方展開個股清單（inline expand），不用左右分欄。
- 兩種模式共用同一套資料與互動邏輯，只有「明細顯示位置」不同（固定側欄 vs inline 展開），用 RWD 斷點（建議 768px）判斷，不用維護兩套獨立邏輯。

### 資料層級：兩層點擊（不是原本的三層）

- **第一層**：主族群（META，41 個）排行榜，依漲跌%排序（可切換升降冪，取代原本獨立的 Top10 區塊——列表本身由高到低排序，最上面就是今日漲幅最大，不用重複維護一份 Top10）
- 點擊主族群 → **直接**顯示底下所有個股清單（不再需要先點子族群才看得到股票）
- 個股清單內用**子族群名稱當分類標籤**（例如「電腦系統業」「伺服器機殼」）把股票分組排列，保留子族群的分類資訊，但不佔用一次額外點擊/導覽層級

### Top10 移除

- 原本首頁最上方有獨立的「▲ 漲幅 Top10 / ▼ 跌幅 Top10」區塊，內容跟主列表前段重複（違反 `DESIGN.md` 既有原則「不重複資訊」）
- 新版拿掉這個獨立區塊，排行榜清單本身＋排序方向切換（▲/▼）就取代了它的功能

### 巨量換手訊號移出範圍

- 原本首頁有「巨量換手訊號」表格（前日漲停→今日爆量收跌）
- 這次直接從 `index.html` 移除，之後跟 `chips.html`／`patterns.html` 一起搬到新的「策略」分頁（見下方「不在這次範圍」）

## 訊號呈現設計

### 統一色條容器

排名變化、連漲連跌、量能異常等訊號，不再各自用不同視覺形式（原本是徽章＋獨立橫幅兩種混雜），統一收進**每一列左側的色條容器**：
- 色條粗細/顏色反映訊號強度（例如：多重訊號同時出現 or 排名大幅跳動 ≥5 名 → 粗橘色條；小幅變化 → 細灰色條；無變化 → 無色條，維持乾淨）
- 色條內用**獨立 chip（膠囊狀色塊）**呈現各訊號，不用純文字＋`|`分隔線（辨識度較差）

### 排名變化：日 + 週 雙重呈現

- **日排名**：沿用現有邏輯（`calc_meta_signals` 的 `yesterday_rank`），比較昨日 vs 今日排名
- **週排名（新邏輯，需新寫）**：rolling 比較——今天往前 5 個交易日的累積報酬排名，對比再往前推 5 個交易日的累積報酬排名。跟現有 `cum5`（5 日累積報酬%）概念一致，只是改成排名版本、往前平移一個 5 日窗格
- 兩者分別用「日」「週」小標籤 chip 呈現（例如 `日 #10→#1 ▲9`、`週 #8→#1 ▲7`）
- 視覺上排名變化是**主角**：大字級數字＋大箭頭，跟主要那一行（名次/族群名/漲跌%）同一視覺量級；日/週細節文字放在主要那一行**下方**（不是同一行右側，同一行會太擠、細節文字容易被忽略）

### 沿用現有邏輯（不用改）

累積排名（3d/5d/7d）、連漲連跌天數、量能異常（今日量/前5日均量 ≥1.5倍）——這三項程式邏輯已 review 過確認正確，這次只改**呈現方式**，不動計算邏輯。

## 元件拆分（初步）

- `App` — 根元件，管理選中族群、排序方向、RWD 斷點
- `RankList` — 排行榜清單（第一層）
- `SectorDetail` — 選中族群的個股清單，依子族群分組顯示（桌機固定面板／手機 inline 展開，共用邏輯）
- `StockRow` — 單一個股列
- `StockModal` — 點擊個股列彈窗（sparkline 長條圖＋外資/投信/融資籌碼明細）——沿用現有功能，不改邏輯
- `SignalChips` — 日/週排名變化＋連漲連跌／量能異常的統一色條＋chip 元件
- `SearchBar` — 搜尋——沿用現有功能

## 沿用不變的既有功能

- 個股 modal（sparkline 長條圖 + 籌碼明細）
- 搜尋
- 表格欄位點擊排序
