## A. 這套系統的骨架（一句話 + 決策脊椎）

**動能派每天的決策順序**（app 若能照這 5 問把答案端出來 = 最大化）：

## B. 逐條對照（規則 → 現有程式 → 缺口 → 資料正確性風險）

### 🔴 B1. 均線口徑：策略用 5/10/60MA，程式算的是 20/50MA
- **筆記**：二、均線是一切的基礎 —— 核心是 **5MA（最敏感，下彎=偏空）、10MA（強勢拉回加碼）、
  60MA（季線，壓著打=走空一律不碰）**。
- **程式現況**：`screener/technical.py::calculate_all()` 只算 `sma20 / sma50 / rsi / adx /
  bollinger`（美股慣例週期），**沒有 5/10/60MA**。
- **而且**：`calculate_all()` 全 repo **沒有任何 caller**（grep 驗證）→ 實質是**死碼**，掃盤主
  流程根本沒用到它。唯一真的算均線的是 `patterns.py::detect_breakout_confirm`（見 B3），它自己
  算 MA5/MA20/MA60，用的是 **MA20 不是策略的 MA10**。
- **缺口**：沒有一個「當地基」的均線模組給整個掃盤流程用；口徑也跟作者對不上（20 vs 10）。
- **建議修法**：`technical.py` 新增 `ma5/ma10/ma60` + `ma_slope`（下彎判斷）+ `ma_bull_stack`
  （多頭排列 close>MA5>MA10>MA60）；並決定 `calculate_all` 是要接進主流程還是刪掉（現在是死碼）。
- **⚠️ 資料正確性風險**：`rolling(5)` 遇到 daily_prices 有**交易日 gap**（參考稍早 07-07 gap 事件）
  會算到「日曆最近5筆」而非「連續5個交易日」→ 均線失真。均線計算前要確保資料連續，或明確以
  trade date 對齊。

### 🔴 B2. 出場三原則：策略最重視、程式完全沒有
- **筆記**：三、出場三原則（核心風控）—— **(1) 跌破5MA (2) 5MA下彎 (3) 重挫長黑，三者同時才出**。
  另有 二十二、持股健檢（空頭排列/均線下彎/跌破頸線）、五十二、空頭確立（後高不過前高＋後低破前低）。
- **程式現況**：`screener/` 裡**找不到任何出場/持股健檢訊號**。整個掃盤偏「進場/形態」，
  風險側是空白。`patterns.py` 有偵測「雙頂/三角跌破」但那是空方形態，不是「持股出場檢查」。
- **缺口**：沒有「手上這批股票今天有沒有觸發出場」的每日健檢。
- **建議修法**：新增 `scan_exit_signals()`：對持股（或全 universe）逐股判
  ①close<MA5 ②MA5 今日<前一日（下彎）③今日長黑（change_pct 夠負 + 實體夠大）→ 三者同時標紅燈；
  另外可加二十二的空頭排列（MA5<MA10<MA20）當「已經該退」的更強警示。
- **為什麼優先**：筆記反覆講「活下來最重要」「大賺小賠」。**保命規則比選股規則更能改變長期績效**，
  而這塊程式最缺。CP 值最高。（路線 A 決定先做上層，這條回頭補。）
- **⚠️ 資料正確性風險**：「重挫長黑」需要開盤價算實體（K棒實體 = |close-open|）。open 現況見上方
  「今天深挖發現 2」：CSV 有 open 但 import 丟掉，一行可救回近期；深歷史要重跑回補。修好前「長黑」
  只能用 change_pct 近似（例如 <-4%）。

### 🟡 B3. 進場三原則 / 多頭排列：部分有，但口徑窄
- **筆記**：十一、進場三原則 —— (1) 帶量長紅突破前高/頸線 (2) 創波段/歷史新高 (3) 均線多頭排列。
  四十五、超強勢股切入五要件（連3根漲停確立後，等盤中拉回切入）。
- **程式現況**：`patterns.py::detect_breakout_confirm`（「多頭拐點」，554 行）**有**實作多頭排列
  `close>MA5>MA20>MA60` + MA5/MA20 上揚——**這是最接近進場邏輯的一塊**。複合評分給「多頭拐點」+15。
- **缺口/口徑問題**：
  - 用 **MA20 不是策略的 MA10**（跟 B1 同源）。
  - 它**限定「MA60 走平後才轉折」**（591 行 `ma60_chg` 要在 ±5% 內）→ 是**特定型態**（長期盤整
    後啟動），不是通用的「動能追強」。策略的追強是「已在多頭排列 + 創新高就追」，不要求 MA60 走平。
  - 「創波段/歷史新高」**沒有獨立訊號**（只隱含在部分形態裡）。
- **建議修法**：新增一個通用「多頭排列＋創新高」掃描（不限定 MA60 走平），跟現有「多頭拐點」並存
  （一個抓啟動、一個抓續強）。
- **⚠️ 資料正確性風險**：「創新高」要小心用**還原股價**還是**原始股價**——除權息當天原始價會跳空
  下修，用原始價會誤判「跌破/沒創新高」。參考 project_data_sync_gap（yfinance 存還原股價那件事）。

### 🔴 B4. 相對強弱（RS）：動能派第一/二層選股，程式沒有
- **筆記**：十九、中醫把脈（個股 vs 大盤、個股 vs 同族群）；四十、指標股觀察；十二、族群集中。
  核心：「同族群大漲時只漲4%的那檔=外強中乾」「主流類股才是第一層選股」。
- **程式現況**：`processors/performance.py` 有算**族群績效**（calc_meta_performance 等），但
  **沒有「個股在族群裡是強是弱」的相對排名**，也沒有「個股 vs 大盤」的超額報酬。grep RS 全空。
- **缺口**：問題 1（主流族群）app 有一半；問題 2（族群內選龍頭）完全缺。
- **建議修法**：
  - 族群層：族群近N日報酬排名（部分有，可加「加速度」＝本週 vs 上週，呼應 mockup v5）。
  - 個股層：`個股近N日報酬 − 所屬族群中位數` = 族群內相對強弱；`個股 − 大盤(加權指數或 universe
    等權)` = 大盤相對強弱。標出每族群的龍頭（RS 最高那檔）。
- **⚠️ 資料正確性風險**：族群中位數/大盤基準要**排除當天缺資料的股票**（別讓 NULL 污染中位數），
  跟先前 `partial_coverage` 同一類防呆。用 `get_rolling_returns` 已算好的近N日報酬當基礎最省事。

### 🔴 B5. 連續漲停鎖死：最強型態，沒偵測
- **筆記**：三十六（持股最好天天漲停鎖死）、四十五（連3根漲停確立強勢）、四十（指標股）。
- **程式現況**：`screener/signals.py` 只看**昨天一天**是否漲停（`prev_change_pct>=9.5`）——而且它
  的用途是抓「**漲停打開/隔日沖倒貨**的轉折」（爆量收跌不鎖跌停），**不是**在找「正在連續鎖死的
  強勢股」。兩者是**不同用途，不衝突**。
- **缺口**：沒有「這檔已連 N 根漲停、還在鎖」的偵測——動能派最該追/最該續抱的型態，掃盤雷達看不到。
- **建議修法**：新增 `scan_consecutive_limit_up()`：連續幾日 `change_pct >= 9.5`（可加「量縮鎖死」
  ＝漲停日量遞減 = 惜售最強）。輸出連板數，供排序與「最強型態」標記。
- **⚠️ 資料正確性風險**：台股漲停幅度非固定 10%（早期/特殊股不同），且**興櫃無漲跌幅**（見筆記
  四十四）。用 `>=9.5%` 近似對上市櫃 OK，但 universe 若含興櫃要排除。另注意處置股搓合日的 change_pct。

### ✅ B6. 已正確對上的部分（不用改，記錄）
- **量能確認**：`patterns.py::_calc_vol_price_score`（量增價漲+2/背離-1）、`signals.py` 的爆量倍數、
  複合評分的 vol_ratio 分級 —— 對上「帶量突破」「量價配合」。
- **籌碼進貨**：`_calc_chips_score`（外資/投信連買 streak）、`calc_meta_chips_signals`、大戶持倉
  —— 對上筆記二十「看進貨有參考性」。注意筆記說**籌碼只給50分、出貨不準**，所以籌碼在複合評分裡
  的權重不宜過高（現況外資25+投信20=45，接近一半，偏高，可討論是否下修）。
- **形態偵測**：雙底/頭肩底/三角/楔型/VCP/多頭拐點 —— 對上「突破頸線/箱型」的進場型態。

- 隔日沖辨識（十五、五十）需要**券商分點進出**資料（目前 repo 無此資料源，backlog 曾提 大戶/分點）。

**最大化 = 把 EOD 能服務的那半（選股候選池＋持股健檢＋族群輪動＋回測驗證）做到位**，

## 附錄：Developer #3 大盤分級儀表板 — Debugger pre-review（資料正確性，待驗證時用）

> Debugger 讀過 plan/spec 後、實作前先記下的資料正確性隱憂。**尚未驗證**（等 Developer 做完）。
> 整體評價：兩軸分離（方向 vs 資金集中度）的洞察很對，fallback/封鎖偵測/門檻待回測都有想到，設計紮實。
> 以下是實作時容易踩、值得先盯的點：

1. **🔴 資金集中度的「非權值股」必須排除權值股本身**：`calc_capital_concentration` 的 `broad_avg`
   若用「全 universe 平均」，2330 等權值股會**同時**被算進權值股籃跟廣度籃 → 落差被稀釋、算錯。
   `broad = universe MINUS heavyweight_ids`，不是 universe 全體。（已查 universe：1038 檔、**一股一列
   無重複**，所以廣度本身不會重複計數，但集中度的兩籃要明確互斥。）

2. **🟡 equal-weight vs cap-weight 的語意**：`heavyweight_avg_pct` 是前20大的**簡單平均**（每檔等權），
   但 TAIEX 是**市值加權**，光 2330 就約佔指數 30%。用簡單平均比較兩籃「平均漲跌」，對「資金集中度
   落差」這個相對比較 OK，但要知道它**不等於**「權值股實際貢獻了多少指數點數」。文件標清楚是等權平均即可。

3. **🟡 廣度的母體 vs TAIEX 的母體不一致**：`breadth_ratio` 是對 **universe（1038檔，含 TWSE+TPEx）**
   算的；但 TAIEX 指數只含 **TWSE 上市**。用「TWSE 指數方向」配「TWSE+TPEx 廣度」是輕微的
   apples-to-oranges。可接受（廣度本來就想看全市場參與度），但 spec 應註明廣度母體是 app 的 universe，
   不是「TAIEX 成分」。

4. **🔴 change_pct 的 NULL/NaN 污染**：廣度與兩籃平均都吃 `daily_prices.change_pct`。除權息當天、

   `pd.isna` 過濾（這是專案重申多次的老雷：`pd.NA`、DuckDB DOUBLE NULL→NaN）。

   的 per-stock fallback 邏輯一致，別各退各的。
