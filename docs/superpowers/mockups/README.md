# index.html 重新設計 — Mockup 沿革

存放 `docs/index.html`（族群總覽頁）重新設計過程中做的 HTML mockup，依時間序保留每一版，方便換平台/換 session 後接續討論，不用重做。用瀏覽器直接開啟 `.html` 檔即可看外觀（不需要跑 server）。

## 版本

1. **2026-07-07-index-v1-flat-ranklist.html** — 第一版方向定案：扁平排行清單取代三層卡片，兩層點擊，左側排行清單＋右側明細面板，桌機/手機兩種版面。深色系（沿用 chips.html/patterns.html 既有色票）。Cody 認可此方向。

2. **2026-07-08-index-v2-anomaly-dark.html** — 新增「異動族群」模組：獨立於例行排行之外，只顯示同時符合多重訊號的族群。兩種訊號類型：
   - **爆量暴衝**：`vol_ratio ≥ 1.5` 且 `|昨日排名-今日排名| ≥ 10`
   - **連續穩步噴出**：`streak ≥ 5`（連漲≥5日）且 `cum7 > cum5 > cum3`（累積報酬持續加速）

   仍是深色系。

3. **2026-07-08-index-v3-cream-ledger.html** — Cody 要求改成米色/質感路線（提到之前有做過米色版但已遺失）。改用「財經帳冊」調性：羊皮紙米色背景、serif 標題（Georgia系）、帳冊墨藍作結構強調色（不是紅/綠，不跟漲跌撞色）、赭黃/酒紫給異動族群兩種訊號語意。刻意避開「米色+赤陶色」這種常見 AI 樣板配色組合。Cody 認可此配色方向（"這就滿像的"），但要求質感再提升、且要重新探索族群排行的呈現方式（不要只是清單）。

4. **2026-07-08-index-v4-heatmap-vs-bar.html** — 目前最新版。沿用 v3 米色帳冊配色，質感細節提升（紙紋理背景、更講究的懸浮陰影層次、更細緻的分隔線）。新增可切換的兩種族群排行呈現方式（用今天真實 41 族群完整資料）：
   - **熱區格（Heatmap）**：41 族群一次攤開，色塊深淺=漲跌幅度
   - **發散長條排行**：由中線延伸的橫條，長度=漲跌幅度，由上到下排序

   **Cody 反饋「資訊不夠多」**——具體提出想看到的資訊：突然爆發的族群跟上週的差異，以及這週表現好的族群上週表現如何。

5. **2026-07-09-index-v5-week-accel.html** — 回應上一版的「資訊不夠多」反饋。新增「本週 vs 上週」欄位：
   - 用真實資料驗算範例：功率半導體上週 -4.17%、本週 +17.76%，加速度 +21.93pt（複利計算，本週=最近5個交易日、上週=再往前5個交易日，跟現有 `cum5`/`get_rolling_returns` 的 rolling window 慣例一致，不是自然週 Mon-Fri）
   - 視覺呈現：小型雙點折線圖（slopegraph）——左點=上週、右點=本週，線的顏色隨加速方向變化（紅=加速、綠=減速），旁邊標加速度數字（百分點）
   - 熱區格跟發散長條排行都有這個新欄位；異動族群卡片的「連續噴出」說明文字也從「7d>5d>3d」改成更直白的「上週X% → 本週Y%，加速+Zpt」
   - 全 41 族群真實資料：功率半導體/機器人自動化/半導體材料 加速度最高（+21.9/+12.8/+11.3pt），被動元件/太陽能/載板 正在減速（負值）
   - 加速度單位確認為 `pt`（percentage point，兩個百分比直接相減），不是相對百分比變化，避免跟一般 `%` 混淆
   - 週期定義確認：Cody 要的是「上週三到本週三」這種同星期幾對同星期幾的概念，跟現有滾動5個交易日算法本來就是同一件事，不用改；不需要嚴格對齊日曆週一~週五

6. **2026-07-09-index-v6-clarity-audit.html** — Cody 提出核心原則：「所有數據都是我懂得、我可以用到的」，不要有看不懂的裸數字。逐項校對 v5 修正：
   - 爆量暴衝卡片拿掉重複的裸數字「排名跳動+19」（跟上面「昨日#21→今日#2」重複，且無單位）
   - 「量比1.1x」→「今日量能1.1x於5日均量」，補上比較基準
   - 漲跌檔數「▲9 ▼6」→「▲9檔 ▼6檔」，補單位（熱區格+長條排行都改）
   - 發散長條排行新增欄位標題列（名次/族群/今日漲跌%/漲跌家數/上週→本週），原本完全沒有欄名
   - 順便修正晶圓代工卡片原本只顯示「今日排名#3」缺昨日對照的不一致，補成「昨日#15→今日#3」

7. **2026-07-14-index-v7-signal-fidelity.html** — Debugger review v6 後提出 5 個具體問題，逐項修正（設計評論見同日 `debug-tasks.md`/對話紀錄，未另開 spec）：
   - **Slopegraph 刻度失真**：原本用全部族群的 min/max 當刻度，功率半導體 +21.9pt 的極端值把其他族群的線拉成幾乎看不出角度的假平線。改成固定 ±8pt clamp，超過封頂但方向保留，一般族群的小幅加速/減速終於看得出真的線形。
   - **顏色語意衝突**：slopegraph 原本用紅/綠表加速/減速，跟熱區格本身「今日漲跌」的紅/綠語意衝突（同一個 tile 可能今日跌但本週比上週加速）。線條改中性墨色，方向改由旁邊的加速度數字顏色單獨表達。
   - **熱區格沒有任何判讀說明、看不出排名**：加一條圖例說明條（色塊=今日漲跌、角標=排名、底部折線=加速度）+ 每格右上角加排名角標。
   - **長條排行族群名可能截斷**：欄寬 112px→132px，加 `title` 屬性當 fallback；表頭改 sticky，捲動到後段仍看得到欄名。
   - **異動族群橫向捲動沒有視覺提示**：加右側漸層遮罩 + 「可左右滑動」提示文字。

8. **2026-07-14-index-v8-magnitude-encodings.html** — Cody 反饋 v7 的「發散長條」在真實資料範圍很窄
   （這批 41 族群今日漲跌% 只有 -2.93%~+2.03%）時，長條長度差異小到看不出來，長度這個視覺通道沒
   被用滿。並排 3 種方案比較（同一批真實資料，只拆「族群排行」單獨比較，不含完整頁面其他區塊）：
   - **① 窄版長條**：延續發散長條語彙，上限從 40%縮到 22%，欄位變窄
   - **② 熱力膠囊**：拿掉長度通道，改用固定寬度色塊＋顏色濃淡（跟熱區格同一套色階邏輯）＋數字疊字
   - **③ 固定刻度圓點**（bullet chart）：軌道固定 ±3% domain，用點的位置表達數值，不受任何離群值
     影響（呼應 v7 修過的 slopegraph 刻度失真問題，這次直接用固定 domain 從根本避開同類問題）
   - **尚未定案**：三選一還是其他組合，待 Cody 看過三版實際渲染後反饋

9. **2026-07-14-index-v9-heatgrid-only.html** — 族群排行呈現方式**定案：熱區格**。Cody 看完 v8
   的三種列表方案後反饋「方格比較好」，直接拍板用熱區格，發散長條／v8 的窄版長條／熱力膠囊／固定
   刻度圓點都不採用。這版拿掉切換鈕，只留熱區格；順帶把色階從 10%~44% 加強到 16%~78%（這批資料
   範圍窄，舊色階深淺差異不夠明顯，既然定案只用這個呈現方式，可讀性更重要，直接加強）。異動族群、
   排名角標、slopegraph 固定刻度修正都原封不動沿用 v7。
