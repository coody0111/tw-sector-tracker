## 1. v2 修正目標

v1 已正確整理出「大盤 → 主流族群 → 族群龍頭 → 進場 → 出場 → 最強型態」的流程，但有四個
不能直接上線的問題：

1. 把技術狀態直接翻成「隨時加碼／直接出清／反手放空」，超過資料能支持的結論。
2. 用近 5 日 `rs_market_score` 代替急殺當日的抗跌程度，週期不一致。
3. 跌停鎖死時使用「立刻砍／反手放空」等可能無法成交的執行指令。
4. 所有主要門檻尚未回測，卻使用確定性的命令文案。

v2 的核心原則：

> **狀態是狀態、證據是證據、候選是候選；未持有個人倉位資料時，不產生「你應該買賣」的指令。**

## 2. 決策模型：四層而不是一個動作標籤

```text
第一層：市場操作許可
    ↓
第二層：主流族群優先序
    ↓
第三層：個股技術狀態
    ↓
第四層：進場候選／持有風險／等待
```

四層必須分開保存與顯示，不把任一單一分數當成最終動作。

### 2.1 市場操作許可

沿用 `classify_market_regime()` 的五級市場資料，但 UI 收斂成三種許可：

| 市場資料 | 操作許可 | 頁面語意 |
|---|---|---|
| 大漲／小漲 | `normal` | 正常尋找進場候選 |
| 持平或指數／廣度背離 | `selective` | 只看條件完整的強勢候選 |
| 小跌／大跌 | `defensive` | 停止一般追價，優先顯示抗跌與持有風險 |

限制：

- `classify_market_regime()` 現有門檻仍未回測，頁面須顯示「實驗性市場分級」。
- 指數日、個股行情日、法人資料日必須分開顯示。
- 指數與個股行情日期不同時，操作許可降級為 `unknown`，不輸出市場操作文案。
- 指數大跌但廣度偏強等背離情況，不可簡化成一般「持平」；UI 必須額外顯示背離原因。

### 2.2 主流族群優先序

首頁與逆轟頁共用 `calc_meta_observation_scores()`，不再另外寫一套主流族群公式：

```text
30% 相對強度
25% 族群廣度
20% 延續性
15% 成分股量能參與
10% 籌碼確認
```

此分數名稱固定為「觀察分」，用途只有：

- 決定哪些族群優先展開。
- 協助區分主升、轉強、急彈、等待確認、轉弱。
- 不直接產生買進或加碼動作。

資料不足時按可用權重重算，並顯示 `score_coverage`。籌碼涵蓋不完整時排除籌碼項，不補零分。

### 2.3 個股技術狀態

沿用 `scan_momentum_health()` 的五級名稱，但取消強制動作映射：

| 狀態 | v2 顯示文字 | 判斷用途 |
|---|---|---|
| 超強 | 優先觀察 | 多頭排列且族群內 RS 位於前段 |
| 強 | 趨勢維持 | 多頭排列，強度尚可 |
| 整理 | 等待重新轉強 | 均線糾結，沒有明確方向 |
| 弱 | 風險升高 | 空頭排列，或多頭但族群內明顯落後 |
| 超弱 | 出場條件命中 | 空頭排列且出場三條件同時成立 |

禁止使用：

- 「超強＝隨時加碼」
- 「強＝一定續抱」
- 「弱＝直接出清」
- 「超弱＝反手放空」

原因：`strength_tier` 不知道使用者有沒有持股、成本與倉位，也未包含完整進場量能及可交易性。

### 2.4 最終決策標籤

最終只允許下列非命令式標籤：

| 標籤 | 必要條件 |
|---|---|
| `進場候選` | 市場許可不是 defensive/unknown＋主流族群＋多頭排列創新高＋動能確認＋量能確認 |
| `續強觀察` | 超強／強，但進場閘門尚未全部成立 |
| `等待確認` | 整理、急彈或資料不足 |
| `風險升高` | 弱，或市場進入 defensive |
| `出場條件命中` | 出場三條件同時成立；只陳述訊號，不保證成交 |
| `跌停風險` | 收盤接近跌停；顯示流動性風險，不建議反手放空 |

## 3. 資料定義修正

### 3.1 急殺抗跌必須新增單日指標

現有欄位：

```text
rs_market_score
= 個股近 5 日累積報酬 − universe 近 5 日等權累積報酬
```

它只能描述中短期強度，不能回答「今天大盤急殺時誰抗跌」。v2 新增：

```text
daily_excess_pct
= 個股今日 change_pct − universe 今日等權 change_pct
```

急殺模式候選條件使用 `daily_excess_pct`，不使用 `rs_market_score` 代替。

顯示名稱必須區分：

- `近5日相對市場` → `rs_market_score`
- `今日抗跌差` → `daily_excess_pct`

### 3.2 族群內 RS 樣本信心

`rs_rank_pct` 在小族群會產生假精準：單一成分股必然為 1.0，兩檔股票最差也可能是 0.5。

新增消費端信心規則：

| 有效成分股數 | 信心 |
|---:|---|
| ≥10 | A |
| 5～9 | B |
| <5 | C／低樣本 |

`<5` 時仍顯示 RS，但不能單靠 `rs_rank_pct` 升級成「進場候選」。

### 3.3 出場三原則

現行定義維持三條件同時成立：

1. `close < MA5`
2. `MA5 今日 < MA5 昨日`
3. `change_pct <= -4%`

但第 3 條目前只是「重挫近似條件」，不是 K 棒長黑。直到 `open/high/low` 資料完整前：

- UI 固定顯示「重挫 proxy」。
- 不宣稱已完整重現原始 K 棒長黑。
- `_EXIT_BIG_BLACK_PCT = -4.0` 標記為待回測參數。

`scan_momentum_health()` 應新增向下相容欄位，方便頁面呈現證據：

```text
below_ma5
ma5_slope_down
big_black_proxy
ma5_rising
ma10_rising
```

既有 `exit_3_rule_triggered` 與 `entry_confirmed` 語意不變。

### 3.4 進場閘門與量能

`scan_bullish_alignment_new_high()` 現在只有價格與均線，沒有成交量。v2 改為新增標記而非直接過濾：

```text
volume_ratio_20d
volume_confirmed = volume_ratio_20d >= 1.5
```

門檻 `1.5` 沿用現有專案慣例，但仍為待回測參數。

「進場候選」必須同時滿足：

```text
market_permission in {normal, selective}
sector_state in {主升, 轉強}
strength_tier in {超強, 強}
entry_confirmed is True
stock_id in scan_bullish_alignment_new_high()
volume_confirmed is True
RS 樣本信心不是 C
```

缺任何一項只顯示「續強觀察」或「等待確認」，不自動買進。

### 3.5 連續近漲停型態

現有 `change_pct >= 9.5%` 是漲停近似值，無法證明盤中全程鎖死。v2 顯示名稱改為：

> 連續收近漲停

不再宣稱「鎖死」。

`scan_consecutive_limit_up()` 新增：

```text
breakout_volume_confirmed: bool | None
```

算法維持既有視覺 spec 的設計：連續近漲停起點量 ≥ 起點前 20 日均量 × 1.5。歷史不足回傳 `None`，
不猜測。此欄位是證據標記，不從清單靜默剔除股票。

### 3.6 跌停處理

新增共用常數：

```text
_LIMIT_DOWN_PCT = -9.5
```

它仍是近似值，只能產生 `跌停風險` 標籤。頁面不得顯示：

- 立刻砍（可能沒有成交量）
- 反手放空（未檢查券源、禁空、處置與成交可能性）

頁面提示改為：

> 接近跌停且流動性受限；若為持股，列入最高風險檢查，實際委託仍可能無法成交。

## 4. 頁面資訊架構 v2

```text
逆轟策略.html
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[資料日期與實驗性聲明]

[市場操作許可]
 normal / selective / defensive / unknown
 指數、廣度、資金集中與背離原因

[主流族群 Top 5]
 共用首頁觀察分；點選切換下方個股

[個股決策主表]
 股票｜技術狀態｜族群內RS｜今日抗跌差｜進場閘門｜最終標籤

[展開證據]
 進場：多頭排列創新高／動能確認／量能確認
 出場：跌破MA5／MA5下彎／重挫proxy
 均線：close、MA5、MA10、MA20、MA60
 RS：族群內、近5日市場、今日抗跌差、樣本信心

[急殺風險區]
 僅 defensive 顯示：抗跌候選與跌停風險，沒有放空指令

[連續收近漲停]
 連續天數｜起漲量能｜後續量縮｜資料可信度
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 4.1 主表欄位

| 欄位 | 來源 | 說明 |
|---|---|---|
| 股票 | momentum health | 代號、名稱、族群 |
| 技術狀態 | `strength_tier` | 五級描述，不直接等於動作 |
| 族群內 RS | `rs_rank_pct` | 同時顯示 `#N/total` 與樣本信心 |
| 今日抗跌差 | `daily_excess_pct` | 單日，與近5日 RS 分開 |
| 進場閘門 | B3＋`entry_confirmed`＋volume | 顯示通過幾項，不只給黑箱結果 |
| 最終標籤 | §2.4 | 候選／觀察／等待／風險／出場條件命中 |

### 4.2 文案限制

上線前全文搜尋並禁止下列字樣：

```text
隨時加碼
一定續抱
直接出清
立刻砍
可換入
反手放空
```

除非未來新增持股資料、交易可行性檢查及通過回測，否則不得重新加入。

### 4.3 停利／停損說明

保留「本策略沒有固定停利百分比」的教育說明，但修正文案，避免把單一未回測規則宣稱為完整停損：

> 本頁不使用固定停利目標；持有風險以均線、趨勢與重挫條件共同檢查。目前「重挫長黑」仍以單日
> 跌幅 proxy 近似，因此本頁提供的是風險提醒，不是自動停損委託。

## 5. 回測與可信度要求

### 5.1 未驗證前的產品規則

- 所有分數與門檻標記為「實驗性」。
- 不顯示預測勝率，除非有對應樣本與期間。
- 不使用命令式投資文案。
- 測試通過只代表程式符合規格，不代表策略有效。

### 5.2 回測分流

不能用同一種回測處理所有規則：

| 規則 | 回測方式 |
|---|---|
| B1/B3/B4/B5 進場候選 | D 日收盤後產生訊號，D+1 可成交價進場，測 D+5/D+10/D+20 超額報酬 |
| B2 出場三原則 | 先建立持倉，再逐日模擬直到規則觸發；比較規則出場與固定持有 |
| 市場操作許可 | 分別統計 normal/selective/defensive 下同一訊號表現 |
| 族群觀察分 | 比較 Top 3/5 與單日漲幅 Top 3/5 的後續超額報酬 |

回測必須揭露：

- 樣本數、勝率、平均與中位數超額報酬。
- 最大不利走勢及極端值影響。
- 牛市、盤整、空頭分層。
- 訊號日與可成交日的差異。
- universe 非 point-in-time 的倖存者偏誤。
- 漲跌停無法成交與券源限制。

## 6. 資料與接口變更清單

### `screener/signals.py`

- `scan_momentum_health()`：新增出場三條件子欄位、`ma5_rising`、`ma10_rising`、
  `daily_excess_pct`、RS 樣本數。
- `scan_bullish_alignment_new_high()`：讀取 volume，新增 `volume_ratio_20d`、
  `volume_confirmed`，不改變既有價格命中集合。
- `scan_consecutive_limit_up()`：新增 `breakout_volume_confirmed`。
- 新增 `_LIMIT_DOWN_PCT = -9.5`，只供風險標記。

### `processors/performance.py`

- 共用 `calc_meta_observation_scores()` 作為族群優先序。
- `classify_market_regime()` 後續需支援背離狀態與資料日期檢查；在修正前由 generator 做降級顯示。

### `export/momentum_generator.py`

- 新建獨立 generator。
- 只組合共用資料，不重寫掃描與分類公式。
- 所有展開控制使用 button/details，支援鍵盤、焦點樣式與 `aria-expanded`。
- 數字使用 tabular figures；狀態不能只靠顏色。

### `main.py`

- 同一天只呼叫每個 scanner 一次，再把結果傳給 generator。
- 任一資料源日期不一致時傳入 freshness 狀態，不由 generator 猜測。

## 7. 驗收條件

### 資料層

- [ ] `daily_excess_pct` 使用單日資料，不誤用 5 日 RS。
- [ ] 小族群顯示低樣本信心，不能單靠百分位產生進場候選。
- [ ] 出場三條件子欄位與 `exit_3_rule_triggered` 完全一致。
- [ ] B3 回傳量比與量能確認，但不破壞既有價格命中集合。
- [ ] B5 起漲量能歷史不足時回 `None`。
- [ ] 跌停只產生風險標籤，不產生放空指令。
- [ ] 所有計算以 `trade_date` 截止，沒有 look-ahead。

### UI

- [ ] 頁面首屏能回答：市場許可、主流族群、第一優先個股及其標籤。
- [ ] 主表同時顯示技術狀態與最終標籤，兩者不混為一談。
- [ ] 展開列能看見每項進出場證據及資料缺口。
- [ ] 日期不同時顯示 `unknown`，不提供市場操作文案。
- [ ] 全頁不存在 §4.2 禁用的命令式文案。
- [ ] 桌機 1440/1920、平板及手機無水平溢出。
- [ ] 色彩之外仍有文字或符號表達狀態。

### 測試

- [ ] 保留既有 `tests/test_signals.py` 測試。
- [ ] 補單日抗跌與 5 日 RS 不混用測試。
- [ ] 補 1/2/4/5/10 檔族群的 RS 信心邊界測試。
- [ ] 補 B3/B5 量能確認 True/False/None 測試。
- [ ] 補資料日期不一致時禁止輸出市場許可的測試。
- [ ] 補 generator 禁用文案回歸測試。

## 8. Out of scope

- 個人持股成本、倉位與損益追蹤。
- 自動下單、券源查詢與融券可行性。
- 盤中兩次下殺的完整「弱中透強」版本。
- 固定百分比停利／停損。
- 還原股價與完整歷史 open/high/low 回補。
- 處置股、興櫃及特殊交易制度的完整判斷。

若未來加入 portfolio，才能另開 v3 設計「續抱／加碼／減碼」等個人化動作；在此之前，本頁固定維持
掃描與決策支援定位。
